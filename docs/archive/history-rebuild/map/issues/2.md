# #2 Symlinked folders look the same as real folders in list and grid views [CLOSED]

## Problem

Nothing in a listing shows that a folder is a symbolic link, so a link cannot be told from a real folder before it is opened, moved or deleted.

## Cause

`Item` had no symlink-directory state; the scan follows links and keeps only the target's metadata.

## Fix

New `Item.is_symlink_dir`, set at scan time for local and GIO entries (`item_from_entry`, `item_from_gvfs_info`, `network_scan`, which now requests `standard::is-symlink`), trash entries and search results. A link badge (`res/icons/emblem-symbolic-link.svg`) is drawn at the icon's bottom-left in grid, list, compact and drag-preview views, from cached state only.

Landed in 66dac3f (feat: improve file browsing and show symlink folder badges).

## Tests

All five tests in `tests/symlink_badges.rs`; `mounter::gvfs::tests::symlink_folder_badges_are_loaded_by_gio_directory_listings`; also `trashed_symlink_folder_badges_use_the_stored_path`.

## Upstream

A feature that pop-os/cosmic-files `master` (4efe802) does not have.
