# #28 Launching with a path on a slow mount delays startup [CLOSED]

## Problem

Starting the app with path arguments on a slow mount delays the first window.

## Cause

`init` called `path.is_file()` per argument and `run()` canonicalized each one.

## Fix

`run()` joins relative paths onto the current directory, and `Message::OpenLaunchLocations` resolves them off the UI thread. A missing path now opens an empty tab instead of being skipped.

Landed in 66dac3f (feat: improve file browsing and show symlink folder badges).

## Tests
