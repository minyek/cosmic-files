# #46 A failed default-application change can corrupt mimeapps.list [CLOSED]

## Problem

Setting a default application when the disk is full or over quota can truncate `mimeapps.list`, losing every default.

## Cause

`set_default` (`src/mime_app.rs`) rewrote the file in place with `fs::write`.

## Fix

`write_default_at` resolves symlinks, stages the new file, keeps permissions and replaces the file atomically; an ordered (FIFO) writer keeps changes in submission order.

Landed in 66dac3f (feat: improve file browsing and show symlink folder badges).

## Tests

`failed_default_write_preserves_existing_preferences`, `default_write_preserves_symlink_and_permissions`, `default_write_preserves_a_dangling_symlink`, `queued_defaults_preserve_both_mime_preferences`, `queued_defaults_keep_the_last_submitted_preference`, `a_failed_default_write_does_not_stop_the_queue`, `a_default_barrier_waits_for_the_preference_write`.
