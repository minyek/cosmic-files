# #35 Constant file changes stack up rescans until memory runs out [CLOSED]

## Problem

Under a steady stream of file events, every debounce tick started another full scan. Scans competed for I/O, memory reached about 189 GB, and the process needed `SIGKILL`. An older, slower scan could also overwrite a newer listing.

## Cause

`NotifyEvents` (main window and picker) started a scan without checking for one already running, and results were matched only by location.

## Fix

`ScanState` (`src/scan/state.rs`) tracks a generation, the running scan and one pending follow-up, for tabs, the Trash and Recents; a completion must match the current scan.

Landed in 66dac3f (feat: improve file browsing and show symlink folder badges).
