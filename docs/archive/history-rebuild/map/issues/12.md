# #12 Startup and the sidebar freeze while the Trash on every mount is checked [CLOSED]

## Problem

With NTFS or CIFS mounts, startup took over a minute and menus stalled.

## Cause

`Trash::icon`, `icon_symbolic` and `is_empty` (`src/trash/mod.rs`) count the trash's entries (through GIO, or by walking every mount's trash), and the sidebar, both context menus and trash items call them while drawing.

## Fix

`is_empty_cached` reads a `TrashState` refreshed off the UI thread at startup, by the trash watcher and after operations; only the latest refresh publishes.

Landed in 66dac3f (feat: improve file browsing and show symlink folder badges).

## Tests

`trash::tests::the_icon_reads_the_cache_the_refresh_publishes`, `review_an_old_trash_result_cannot_overwrite_a_newer_result`, `a_superseded_trash_result_cannot_publish_while_the_latest_is_pending`.

## Upstream

The defect is present in pop-os/cosmic-files `master` (4efe802).
