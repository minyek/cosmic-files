# #32 Recent-files history is rewritten on the UI thread at every file open [CLOSED]

## Problem

Opening a file blocks while `recently-used.xbel` is read, changed and written back.

## Cause

`update_recently_used` and `clear_recently_used` ran inline at five call sites and in the file picker.

## Fix

One ordered (FIFO) worker in `src/recents.rs` records, clears and removes entries; `persistence::flush` drains it, and the default-app writer, before a clean exit or before the picker returns.

Landed in 66dac3f (feat: improve file browsing and show symlink folder badges).

## Tests

`recents::tests::recents_mutations_follow_submission_order`, `a_failed_recents_mutation_does_not_stop_later_updates`, `a_barrier_waits_for_preceding_mutations_without_applying_another`; `app::tests::clean_exit_waits_for_queued_persistence`; `dialog::tests::framework_close_waits_for_queued_recents_before_publishing_its_result`, `a_picker_result_waits_for_persistence_before_closing`; also `save_waits_for_queued_recents_before_publishing_its_result`, `cancel_waits_for_queued_recents_before_publishing_its_result`.

## Upstream

The defect is present in pop-os/cosmic-files `master` (4efe802).
