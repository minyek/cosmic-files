# #17 An open sidebar context menu stats its entry on every frame [CLOSED]

## Problem

While a sidebar entry's context menu is open, the entry is checked on disk on every frame, which blocks on slow mounts.

## Cause

`nav_context_menu` called `is_file()` and `is_dir()` while the sidebar was rebuilt.

## Fix

The facts load off the UI thread (`NavBarContext`, `NavContextInfoLoaded`), and actions that depend on the entry's type wait for them.

Landed in 66dac3f (feat: improve file browsing and show symlink folder badges).

## Tests

`review_a_pending_sidebar_stat_does_not_offer_directory_actions`, `sidebar_actions_follow_loaded_file_and_folder_metadata`, `virtual_sidebar_locations_do_not_wait_for_path_metadata`, `sidebar_metadata_from_an_older_menu_cannot_replace_current_facts`.

## Upstream

The defect is present in pop-os/cosmic-files `master` (4efe802).
