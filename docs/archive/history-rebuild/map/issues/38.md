# #38 Operation history grows for the whole session [CLOSED]

## Problem

The record of completed and failed operations is never trimmed, so memory grows with every operation.

## Cause

`complete_operations` and `failed_operations` in `src/app.rs` were never pruned.

## Fix

`cap_operation_history` keeps the newest 256 entries (`MAX_OPERATION_HISTORY`); retrying an extract whose entry was dropped is skipped instead of panicking.

Landed in 66dac3f (feat: improve file browsing and show symlink folder badges).

## Tests

`cap_operation_history_keeps_the_newest_and_bounds_growth`, `retrying_an_evicted_operation_skips_instead_of_panicking`, `retrying_an_extract_carries_the_password`, `retrying_a_non_extract_operation_is_refused`.

## Upstream

The defect is present in pop-os/cosmic-files `master` (4efe802).
