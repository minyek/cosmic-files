# #21 Pasting an image, video or text writes the file on the UI thread, with a name race [CLOSED]

## Problem

Pasting clipboard content blocks the window while the file is written, and two pastes could pick the same name.

## Cause

`copy_unique_path` followed by `fs::write` ran inline; choosing the name and then writing it is a race.

## Fix

`write_unique_file` runs off the UI thread and creates the file with `create_new(true)`, retrying on a name clash.

Landed in 66dac3f (feat: improve file browsing and show symlink folder badges).

## Tests

`pasted_files_preserve_existing_content`, `concurrent_pastes_keep_both_payloads`.

## Upstream

The defect is present in pop-os/cosmic-files `master` (4efe802).
