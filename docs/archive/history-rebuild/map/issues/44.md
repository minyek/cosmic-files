# #44 A compress that fails while finishing the archive is reported as a success [CLOSED]

## Problem

A truncated or corrupt `.tar.gz` or `.zip` can be left behind, for example when the disk fills at the end, and the operation still reports success.

## Cause

For TGZ only `tar::Builder::finish` was called; the gzip trailer and the buffered-writer flush happened on drop, which ignores errors. ZIP never flushed its buffered writer explicitly.

## Fix

TGZ calls `into_inner`, `GzEncoder::finish` and `flush`, and ZIP calls `finish` and `flush`, all with errors propagated.

Landed in 66dac3f (feat: improve file browsing and show symlink folder badges).

## Tests

`zip_finalization_failure_leaves_no_destination_or_staging_file`, `tgz_finalization_failure_leaves_no_destination_or_staging_file`.
