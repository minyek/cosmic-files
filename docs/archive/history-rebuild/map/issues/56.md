# #56 Idle compio io_uring runtime is counted as IO wait: session IO pressure ~50% with no IO (needs IORING_ENTER_NO_IOWAIT, compio-driver >= 0.12.4) [CLOSED]

## Problem

An idle cosmic-files makes its login session look permanently IO-stalled: the session's IO pressure reads about 50% while the process does almost no IO.

## Cause

cosmic-files uses compio with its io_uring driver (`compio = "0.18"`, which resolves to `compio-driver` 0.11.4). When idle, the driver waits on its notifier eventfd with `submit_and_wait` without `IORING_ENTER_NO_IOWAIT`, so the kernel counts the waiting runtime thread as in IO wait.

## Upstream fix

compio fixed this in compio-rs/compio#957, "fix(driver,iour): set IORING_ENTER_NO_IOWAIT on CQE wait", released in `compio-driver` 0.12.4 (2026-07-06). `compio` v0.19.2 depends on `compio-driver` 0.12.5. The PR splits the combined submit-and-wait into `submit()` followed by a wait-only `enter()` with `GETEVENTS | NO_IOWAIT` when the kernel reports `IORING_FEAT_NO_IOWAIT` (Linux 6.15+).

## Proposed fix

Bump `compio` from 0.18 to 0.19.2 or later, so that `compio-driver` is at least 0.12.4, and adapt to any 0.19 API changes. If the upgrade is too invasive, carry a backport of #957 onto `compio-driver` 0.11.4 as a `[patch.crates-io]` until the upgrade lands.

## Acceptance

- An idle cosmic-files leaves its session scope's IO pressure near 0. Check `full avg10` in `/sys/fs/cgroup/user.slice/user-1000.slice/session-<n>.scope/io.pressure` with cosmic-files open and idle for 60 s or more.
- `/proc/<pid>/task/<tid>/stat` and the scope's PSI no longer show the runtime thread as in IO wait while idle.
- File operations (copy, move, delete, the io_uring paths) still pass the existing tests.

## Fix

`compio` goes from 0.18 to 0.19.2, which brings `compio-driver` 0.12.5. Its driver waits with `IORING_ENTER_NO_IOWAIT` on kernels that support it (Linux 6.15 and later), so an idle runtime is no longer counted as IO wait. compio 0.19 reports a failed task as a `JoinError`, which `operation_error_from_join` maps to an operation error.

## Tests

`a_panicked_task_keeps_its_operation_error`, `a_task_panicking_with_another_payload_reports_an_operation_error`, `a_cancelled_task_reports_an_operation_error`. The IO-wait accounting itself was checked by hand: the session's IO pressure stays near 0 with cosmic-files open and idle.
