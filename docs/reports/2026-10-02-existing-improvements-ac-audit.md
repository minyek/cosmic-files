## Verdict and evidence classes

**The existing improvements are not yet eligible for an unconditional sqmerge acceptance verdict.** Most behavioral clauses have implementing code and distinct tests in the fresh candidate matrix. Explicit final-source real acceptance and the planned exclusive performance measurement are outstanding. Two explicit behavioral subclauses lack a discriminating executable pin: archive finalization failures and drag selection after viewport integration. Picker close through the framework exit callback needs targeted closure evidence; source inspection raises a concern but does not establish a reproduced defect.

The parent supplied current successful gate results: minimal 227 unit + 5 integration; default/all 242 unit + 6 integration; application, applet, thumbnailer release builds. I inspected the candidate's integration report and retained verification description. I did not rerun the full gate. Test names below identify candidate tests included in that matrix. MET means the stated behavior is implemented and a discriminating listed test exists, unless the row explicitly says historical manual evidence or source inference. NOT-MET means required execution/evidence is outstanding. GAP means the implementation is present, but the named requirement has no sufficiently discriminating executable evidence in the inspected sources. It does **not** mean a defect was reproduced.

The user's manual statement was exactly “I've tested and looks good.” It establishes general approval of the tested combined application. It supplies no scenario detail and therefore does not establish every delayed-completion, storage-error, protocol, or performance clause.

### Closure work, ordered by dependency

1. **[BLOCK-MERGE / CLOSE-NOW] Final-source acceptance evidence.** Restore/include the existing uncommitted acceptance tools through the parent's authorized artifact workflow; build them against the frozen combined source, rerun storage + initialization failure/recovery, X11 + Wayland menus/image/scroll/watcher scenarios, real picker, and FTP/GVFS MIME parity. The older reports explicitly mark this refresh pending. Refresh hashes, source attribution, reports and honest PR wording after execution. Cost: existing harness runs and artifact maintenance; benefit: closes explicit final-source evidence clauses without changing production behavior.
2. **[BLOCK-MERGE / CLOSE-NOW] Archive finalization-error evidence (readiness AC2).** Add/run an operation-level failure case that reaches ZIP/TGZ encoder/buffer finalization, fails there, observes the operation error, and asserts no destination or leftover stage. Existing missing-source and precancelled-controller tests exercise different failures. A child-process `RLIMIT_FSIZE` fixture with SIGXFSZ ignored is already used for preference-write failure and is a plausible isolated approach. Do not substitute a test of the encoder library alone for the production Operation path.
3. **[BLOCK-MERGE / CLOSE-NOW] Drag-selection evidence (readiness AC10).** Exercise the retained drag callbacks using the actual list/grid widgets with viewport culling and assert the selected set, including a scroll position where earlier rows are culled. Existing view/layout tests and GUI harness sequences do not dispatch a drag-selection gesture. This is a coverage gap, not proof that upstream integration broke selection.
4. **[BLOCK-MERGE / CLOSE-NOW] Picker framework-close evidence (readiness AC4).** Queue persistence, close through the real window/application exit path, and verify the previously queued mutation is complete before returning/exiting. Save/Cancel message closure uses a flush task; `dialog.rs:1383`'s `on_app_exit` instead sets Cancel and returns None. The selected libcosmic `Action::Close` calls this hook, and None invokes framework close directly. Existing picker persistence test covers Save(false), not this callback with a blocked queue. This is an unproven potential defect and an untested universal lifecycle boundary; reproduce before declaring a production defect.
5. **[BLOCK-MERGE / CLOSE-NOW] Exclusive measurement (branch-acceptance plan 4 and readiness plan 6).** Run the existing frame probe exclusively and record environment, sample count, distributions and limits. No fresh numerical speedup claim is required; the written plan nevertheless requires measurement and currently says pending. Keep this out of the routine functional gate.

The unsupported-atomic-rename clause has a separate GAP in the ledger: fail-closed source is intact and supported Linux no-replace behavior is pinned; no test forces the unsupported-primitive error. Its documented non-Linux/unavailable-backend environment limit must remain explicit. A focused injected unsupported result can close the negative contract without requesting or changing an actual shared mount. No speculative portability defect was established.
